# 调研：模型怎么决定"这条片子要不要加剪辑手法"

> 起因：EVO-026 把钩子、推近、音效、去停顿、字幕弹入全加上之后，用户说"剪的不如上次好……剪辑方法不能滥用，不是越多越好，而是精准简洁，不是有什么就堆砌什么"。
> 这份调研只回答一个问题：开源的剪辑 Agent / Skill 是怎么让模型**克制**地用手法的。日期 2026-11-25。

## 2. 共同做法（按出现次数排）

### 2.1 "什么都不加"是合法结果，而且是默认
- cut-as-code 动效：`Zero cues is valid`，"Reject filler"；全部跳过时这一步直接从流程里去掉。
- 仓鼠口播：先有一个**无动效基座**（只剪口误停顿 + 竖屏 + 字幕），动效版建在基座上，是另一个 skill；基座明确"不加 B-roll、图形段、贴纸、信息卡、BGM、音效"。
- duyi：`cue_highlights 每条字幕最多一处；没有明确重点就不标`。
- 【已验证，读了原文】三个项目都把"加手法"放在单独的一步，默认不走。

### 2.2 开关只由用户打开，不由模型打开
- DaVinci："Add BGM only with current-task authorization"。
- zm-talk-visual `bgm.md` 第 7 行："背景音乐是一个开关，不是默认要有的"，开工先问。
- 仓鼠：变速、防抖、人声消音"不主动做，先问用户"。
- cut-as-code 总则："只冻结用户要求的操作，不把路由表变成流水线"。
- 【结论】BGM、音效这类会改变片子气质的东西，配置里默认关，模型无权自己打开。

### 2.3 每个手法要说出"为什么用在这里"，空话不算理由
- cut-as-code：每个 cue 先写内容、目的、时间、理由，再去找素材；每个配方带 `best_for` / `avoid_when`，模型必须逐条回答 `avoid_when`；"never use vague taste words as a substitute for decisions"（"高级""有氛围"这类词不算决定）。
- cut-as-code 的信息预算："Every visible element must earn its place"，"Do not express the same fact as a headline, badge, and caption"——同一件事不要用标题、角标、字幕说三遍。
- 【对照我们】EVO-026 的提示词是"每一项都按内容判断，不合适就不用"，但输出格式要求每项都填，示例里 hook、zoom、sfx 全都填了。模型照着示例全填了：3 段都有钩子、都推近、都有"叮"。

### 2.4 程序设硬门槛，模型说了也不算
- hotclip `coldopen.ts`：笑点离片头不到 **10 秒**就不做前置（`COLD_OPEN_SKIP_NEAR_START_SEC = 10`），不到 **6 秒**不做闪现（`FLASH_SKIP_NEAR_START_SEC = 6`）。原因很直接：片子很短、笑点马上就来，再提前放一遍就是剧透加重复。
- 仓鼠：两个音效至少隔 0.5 秒，"不要用自动配，它会给每个小动作都配一下，太密"；镜头停留中位 ≥ 2 秒。
- 【对照我们】EVO-026 没有"离片头多近就不做钩子"的门槛。我们的片子只有 18～25 秒，今晚 3 段认可片的笑点句分别从第 7.7、8.8、8.2 秒开始，按 hotclip 的门槛一段都不该做前置。吕德华"骂一半秒怂"把笑点句提前，片子 24.9 → 28.0 秒，观众 3 秒内会听到同一句话两遍。

### 2.5 守住用户认可过的版本，新版本要跟它对比
- DaVinci："Preserve approved versions"。
- cut-as-code：`video-to-shorts` 有人工审核关（`REVIEW_REQUIRED` 只能选 revise 或 skip，Agent 不能自己批准）；`video-edit-compare` 把原片和成片并排出对比视频。
- 【对照我们】EVO-026 直接覆盖了 EVO-025 的成片，用户只能凭记忆比较。

### 2.6 剪掉的是废话，不剪"活人感"
- video-alchemy："Never cut: personality phrasing, intentional emphasis, live reactions"。
- DaVinci："Match shot duration to information density and emotion, not a fixed number"。
- 【对照我们】去停顿（tighten）对搞笑片危险：笑点前的停顿往往就是节奏本身（等一拍再说出口误）。

## 3. 对我们项目的改法

| 手法 | EVO-026 | 改成 | 依据 |
|---|---|---|---|
| 竖屏布局、标题、关键词字幕、脏话打码 | 有 | **基座，每条都有**（= EVO-025 用户认可的版本） | 2.1、2.5 |
| 遮掉游戏画面里重复的小窗 | 有 | 默认关（`blur_dup_cam`）：用户看对比后认为模糊色块比两个主播更显眼 | 2.5 |
| 响度统一 −14 LUFS | 有 | 保留（听不出来的技术处理） | — |
| 高亮词 | 最多 3 个、每句 1 个 | **全片最多 1 个**，没有明确笑点词就不标 | 2.1 duyi、2.3 信息预算 |
| 字幕弹入动画 | 默认开 | 默认关 | 2.1 |
| 开场钩子 | 模型自选 | 笑点句离片头不到 10 秒（闪现 6 秒）就禁用；成片超过 20 秒也禁用 | 2.4 hotclip |
| 推近 | 最多 2 处 | 最多 1 处，必须写理由 | 2.3 |
| 去停顿 | 模型自选 | 只删 ≥ 1.5 秒、前后都不是笑点句的空档；必须写理由 | 2.6 |
| 音效 | 最多 3 个，本地合成 | **默认关**（`package.sfx` 开关）；开了也最多 1 个 | 2.2 |
| BGM | 模型可选 light | 默认关，只认配置 | 2.2 |
| 额外手法总数 | 不限 | 每条最多 1 个；**一个都不用是正常结果** | 2.1、2.3 |
| 怎么问模型 | 每项都要填 | 先写"这条片子好笑在哪、观众需要看清什么"，再对每个手法回答"用不用、理由、对应哪句"；示例里所有手法都填"不用" | 2.3 |
| 交付 | 覆盖旧版 | 新版出到新目录，和认可版本一起给用户看 | 2.5 |

## 4. 不采用的做法和原因
- **完全去掉模型决定，只出基座**：最安全，但用户 EVO-026 前提出过"模型自动检测切片需要怎样的剪辑手法"。保留模型决定，但门槛放在程序里、默认值是不用。
- **照搬 cut-as-code 的配方库和审核网页**：它是给长视频加动效图形的，我们只做 20 秒的切片，配方库太重；只借它"zero is valid、逐条答 avoid_when、人工审核"三条思路。
- **让模型打分决定手法强度**：调研里没有项目这么做，分数没有可核实的含义。
