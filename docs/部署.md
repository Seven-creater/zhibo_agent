# 部署到服务器

本文说明怎么把采集、声音感知、判定和出片放到一台 Linux 服务器上长期运行。资源数字来自 2026-11-24 晚在本机（Apple M1）的实测，详见演化记录 EVO-028。

> 【待验证】目前还没有在 Linux 服务器上实际跑过。部署后先运行 `python -m zhibo check`，再试跑一晚，检查三件事：能不能拉到原画、能不能收到弹幕、声音感知会不会积压。

## 1. 机器怎么选

| 资源 | 建议 | 依据（实测） |
|---|---|---|
| 内存 | 4 GB（2 GB 太紧） | 声音模型约 710 MB（几个直播间共用一份）；每个直播间录制 ffmpeg 37 MB，dyhub 浏览器内核约 200 MB（dyhub 文档的数，没实测）；出一段竖屏成片峰值约 950 MB |
| CPU | 2 核起 | 声音感知在 M1 上的处理时间约为音频时长的 0.05～0.08 倍。录制只是复制码流，约占一个核的 3%。出一段 21 秒的成片，在 M1 上 4 个核跑满约 20 秒，2 核服务器会慢几倍 |
| 磁盘 | 40 GB 以上 | 原画约 19 Mbps，每个直播间每小时 8.5 GB；环形缓冲每个直播间常驻约 0.9 GB；两个直播间一晚保留约 7 GB 录像；剩余空间低于 15 GB 时录制器会停录 |
| 带宽 | 每个直播间下行 ≥ 20 Mbps | 原画 1080p60 约 19 Mbps，两个直播间约 40 Mbps。很多便宜云服务器的带宽只有几 Mbps，买之前要确认入方向带宽 |
| 位置 | 中国大陆 | 要拉抖音的直播流。机房 IP 可能被风控：dyhub 文档提到用 Cookie"绕过容器 IP 风控"，我们没有验证过 |

## 2. 安装（以 Debian / Ubuntu 为例）

```bash
sudo apt install -y python3 python3-venv ffmpeg fonts-noto-cjk chromium git curl
```

- Python 要 3.9 以上；Node.js 要 20 以上（发行版自带的可能太旧，可以用 NodeSource 或 nvm 安装）。
- ffmpeg 不需要文字滤镜，文字都用 Pillow 画。
- 中文字体会自动找：macOS 用冬青黑体，Linux 用 Noto Sans CJK。都没有时用 `fc-match` 找一个简体中文字体；还找不到就在配置 `package.font` 里写字体文件路径。

```bash
git clone https://github.com/Seven-creater/zhibo_agent.git && cd zhibo_agent
sh scripts/fetch_models.sh                       # 建 .venv、装 requirements.txt、下载三个模型（约 280 MB）
git clone --depth 1 https://github.com/ymstar/dyhub.git third_party/dyhub
cd third_party/dyhub && npm ci --ignore-scripts && npm run build && cd ../..
export DYHUB_CHROME=$(which chromium)             # Linux 上告诉 dyhub 用哪个浏览器
```

GLM 密钥写进项目根目录的 `.env`（已在 .gitignore 里，不会提交）：`ZHIPU_API_KEY=...`。

## 3. 自检

```bash
.venv/bin/python -m zhibo check
```

自检会逐项检查：Python 版本、ffmpeg、Python 包、模型、中文字体、dyhub、Node、Chrome、GLM 密钥、内存、CPU、磁盘剩余、自动清理是否打开。缺什么就会提示怎么装。带宽没法自动测，要自己确认。

## 3.5 腾讯云实测（2026-11-25，EVO-030）

- **机器**：腾讯云上海 S5.LARGE4，4 核、3.7 GB 内存，Ubuntu 24.04；系统自带 ffmpeg 6.1、Python 3.12。
- **两处在 Linux 上才暴露、已修好的问题**：
  - ffmpeg 6.1 不认 `-/filter_complex`，现在按版本自动改用 `-filter_complex_script`；
  - dyhub 不认 PATH 里的 Chrome，现在启动 dyhub 时自动传 `DYHUB_CHROME`。
- **服务器访问 GitHub、PyPI 很慢**：
  - Node 和 Chrome for Testing 改从 npmmirror 下载（Node 核对了 SHA256）；
  - pip、npm 用腾讯云自带的镜像；
  - 代码和模型从本机直接传上去。
- **弹幕内核选轻量内核（`DYHUB_COLLECTOR=lightweight`）**。浏览器内核一个直播间 Chrome 就占约 1.4 GB（PSS），整机只剩 1.3 GB；轻量内核不开浏览器，弹幕每分钟 418～598 条，和浏览器内核差不多。如果被风控收不到弹幕，再改回 `browser`。
- **声音感知**：处理用时约为音频时长的 0.135 倍（M1 上是 0.05～0.08 倍），没有积压。
- **出片**：一段 18.5 秒的片子用时 34 秒，峰值内存约 600 MB。

## 4. 长期运行

采集要跑几个小时，退出 SSH 后也不能停。可以用 tmux（核心代码不依赖 systemd）：

```bash
tmux new -s zhibo
.venv/bin/python -m zhibo collect --start-hub --hours 4 --room 主播名=直播间号 --room ...
# Ctrl+B 再按 D 离开，tmux attach -t zhibo 回来
```

采集结束后的判定、出片和看结果，跟本机一样（见 README）。也可以用 `scripts/night.sh` 一条命令跑完"采集 → 判定 → 出片"，日志写在 `logs/`：

```bash
MIN_FREE_GB=5 bash scripts/night.sh 4 "陈泽=615189692839" "coke老师=https://www.douyin.com/user/<sec_uid>"
```

## 5. 磁盘清理

- 实时配置 `configs/live.json` 里的 `retention.video_days`（默认 3）：每次开始采集前，先删掉 3 天前数据集里的**画面录像**。
- 整场音频、弹幕、声音感知、逐句稿都很小，会保留，离线重跑检测仍然可以用。
- 不清理的数据集：
  - 有 `labels.json`（人工标注过）；
  - 有 `.keep` 文件；
  - 合成数据集；
  - 符号链接过来的数据集。
- 已经剪好的片子在 `runs/` 下，不会被删。
- 手动清理：先 `python -m zhibo cleanup --days 3` 看会删什么，确认后再加 `--yes` 真删。每次删除都记在该数据集的 `pruned.json` 里。
